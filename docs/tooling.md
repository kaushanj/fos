## New machine setup

1. **Node**: install nvm, then `nvm install` and `nvm use` in the repo root (reads `.nvmrc`; Node 22.13 or newer).
2. **Dependencies**: `npm install`.
3. **Baseline**: `npm run check` and `npx expo-doctor@latest` must pass.
4. **Spec Kit CLI** (only needed to upgrade or re-initialize Spec Kit; the committed `.specify/` and skills work without it): install `uv`, then `uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@v1.2.5`.
5. **Claude Code**: install per the official docs (`https://code.claude.com/docs`), sign in, start `claude` in the repo root, and accept the workspace trust prompt. Then verify discovery:
   - `/skills` lists `orchestrator`, `react-native-testing`, and the `speckit-*` skills.
   - `claude plugin validate .claude/agents` reports no frontmatter errors, and asking "Which subagents are available?" lists `developer`, `reviewer`, and `tester`. (Current `/agents` only prints a reminder.)
   - `/doctor` reports no invalid settings in `.claude/settings.json`.
6. **Jira MCP** (optional): see [MCP](#mcp).
7. **Android device builds**: approach still open ([`project-context.md`](./project-context.md) open question 9). Record the verified command in `CLAUDE.md` once it works.

Machine-specific settings go in `.claude/settings.local.json` (gitignored) or user settings, never in committed files.

## Cursor and Claude Code differences

| Concern | Claude Code | Cursor |
|---------|-------------|--------|
| Instructions | `CLAUDE.md` | Reads `CLAUDE.md` as a workspace rule |
| Skills | `.claude/skills/` | Loads `.claude/skills/` for compatibility (verified 2026-10-31 for `speckit-*`) |
| Agents | `.claude/agents/`; restricts tools with `tools` | Loads `.claude/agents/`. `reviewer` and `tester` set `readonly: true`; `developer` does not. Claude Code ignores unknown fields |
| Permissions | `.claude/settings.json` | Not read; Cursor uses its own approval settings |
| MCP | `claude mcp add`, or `.mcp.json` for project scope | `.cursor/mcp.json` or Cursor settings |

Do not assume a setting in one tool applies to the other.

## Permissions (Claude Code)

`.claude/settings.json`:

- **Allow** without prompting: `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm test`, `npm test -- <args>` (targeted Jest runs), `npm run check`. All are scripts verified in `package.json`. No broad `npm` or shell rules.
- **Ask** every time: `git push` (including forms like `git -C . push`) and every tool from an MCP server named `atlassian`. Atlassian MCP v2 exposes generic tools that can both read and write, so all calls prompt; approve reads, decline writes the task did not authorize.
- **Bypass mode disabled**, because `bypassPermissions` mode would skip the push prompt.
- `.env` files remain readable when a task needs them; there is no deny rule.

Limits: rules match the command text Claude writes. A push run another way (a script, `sh -c`, a wrapper tool) is not matched, so rules reduce risk but are not a security boundary. Permission rules also do not prevent a value that was read from being repeated; the secrets rule in `CLAUDE.md` governs that.

Jira setup for Claude Code (Jira Cloud, OAuth; no token stored in the repo):

```bash
claude mcp add --transport http atlassian https://mcp.atlassian.com/v2/mcp
```

Then run `/mcp` in Claude Code to authenticate. Keep the server name `atlassian` so the ask rule applies. In Cursor, add the Atlassian MCP server through Cursor's MCP settings. If the customer uses Jira Data Center, this server does not apply; paste task details instead until an approved alternative exists.
